> 给**读不到我这个 Obsidian 库**的另一个 AI / 开发者看。库结构、日记格式、取数规则、踩过的坑、参考实现全写在下面，不需要你猜。

## 0. 一句话目标

在 Obsidian 里把**本周 7 天的日记**汇总成一张周报表格：

- **一天几件事就有几行**（一行 = 一个事件）
- **只有「日期」列纵向合并**；事件 / 内心 / 行动 / 结果 / 备注 / 笔记 每行独立，不合并
- 「内心 / 行动 / 结果」**直接从当天日记对应事件的段落里抓**，不要人手抄
- 插进周报文件就能直接显示，不需要事后手改行数和合并坐标

## 2. 输入：单日日记的真实格式

每天的文件由若干「事件块」组成，一个事件块 = 一个二级标题 `## 📌 标题` + 固定四段。
下面是 `Diary/2026/20261123.md` 的**原文**（一字未改，只截了第 2 个事件）：

```markdown
# 20261123

## 📌 阅读《思维的利剑》半小时：唯一想保持下来的习惯
- 重要度:: 3
- 主题:: #日常 #阅读 #学习/方法

### 📝 简述
%% 
[[B_复盘自己#“7 种复盘技巧”|“7 种复盘技巧”]]
一定要真实，描述日常事件，需要说清楚当时是什么事导航第一时间的真实相反和感受，产生了什么行动，事情发生之后产生了怎样的结果？

%%
第一件事：今天用至少半小时的时间阅读了《思维的利剑》中的一章节内容。这个习惯可以保持，最少应该使用半小时的时间。

### 🔍 分析
%%
- 抽象化：
	- [[B_复盘自己#“周度复盘第三步 抽象化”|“周度复盘第三步:抽象化”]]
可以先反思为什么会有那样的想法?当时真正的渴望是什么？是否有更好的方式？
使用不同的视角来改变第一时间打印和感受
%%

- 人物:: 
- 洞察:: 这是今天唯一一条「做成了、并且想保持」的事：半小时、一章，量很小但可重复；句子里的「最少应该使用半小时」说明它在你心里已经是下限，不是目标
- 改进:: 把这半小时挂到一个固定时段（比如早起后、或睡前阅读代替刷手机），否则它会和以前的阅读计划一样，被晚上那 4 小时视频挤掉

### 🎯 计划
%%
提示：工作事件→用 What/Who/When/Where/How/预算
下次遇到这种情况怎么做，谁在什么时间什么地点做什么？
 %%

- What:: 保持每天至少半小时读《思维的利剑》
- When:: 每天（原文只写「最少半小时」，没定时段）

### 🔮 推演
%% 假如这么做了有样的后果 %%
如果这半小时能固定下来，它是今天所有记录里唯一不需要「意志力爆发」就能持续的东西；但如果它没有固定时段，最先吃掉它的就是晚上那 4 小时短视频——顺序上，它永远排在视频之后。

---

## 📌 情绪崩溃花了 30 块买啤酒：缓解了一晚，昏沉留给明天
- 重要度:: 4
- 主题:: #日常 #情绪 #生活成本
（后面同样是 简述 / 分析 / 计划 / 推演 四段）
```

同一天可以有 1—5 个 `## 📌` 块，`---` 分隔。

### 2.1 取数映射表（周报每一格从哪儿来）

| 周报列 | 取日记里的什么 | 备注 |
| --- | --- | --- |
| 日期 | 文件名日期 → `周一 11/23` | 同一天的多行只有第一行写，其余行留空（合并） |
| 事件 | `## 📌 ` 后面的标题 + 指向它的链接 | `[[20261123#📌 阅读《思维的利剑》半小时：唯一想保持下来的习惯\|阅读《思维的利剑》半小时]]` |
| 内心 | `### 🔍 分析` 里的 `- 洞察:: xxx` | 空就写 `—` |
| 行动 | `### 🎯 计划` 里的 `- What:: xxx` + `- When:: yyy` | 拼成 `xxx ｜ yyy`；两行都空写 `—` |
| 结果 | `### 📝 简述` 的正文 | 去掉开头的 `第N件事：` |
| 备注 | **人写**，不是抓的 | 六个状态词之一：新起 / 延续 / 调整 / 转折 / 收束 / 单独；跨周事件再加 `event-2026-0xx`（见 §6） |
| 笔记 | 自动拼 | `[[20261123]] · ★重要度 · 📌×当天事件数`，例：`[[20261123]] · ★3 · 📌×4` |

### 2.2 解析要点（照做，否则取错）

1. **先删掉所有 `%% … %%` 注释块**。每个段落开头都嵌了一段写作提示，不删会把提示当成正文。
2. 段落范围：从 `### 📝 简述` / `### 🔍 分析` / `### 🎯 计划` / `### 🔮 推演` 开始，到**下一个二级或三级标题**为止（正文里可能出现 `#### 1. 专注情况` 这种四级标题，它不算段落边界）。
3. 事件块切分：按行首 `## 📌` 切（正则 `/^##\s*📌\s*/m`），块内第一行 = 事件标题。
4. `- 洞察::` / `- 重要度::` / `- 主题::` 都可能为空或缺失（有时写成 `%% 重要度:: 原文未填 %%`），不要抛错。
5. 一个文件可能 0 个事件（空文件），也可能 5 个；也可能整个文件不存在（那天没写）。
6. 标题里可能含 `：` `「」` `《》` `（）`；**不允许含 `|`**（会破坏 Markdown 表格）。
7. 单元格文本统一处理：合并连续空白、把换行压成空格、超过 150 字截断加 `…`。

## 3. 输出：周报表

### 3.1 列定义（7 列，顺序固定）

| 列 | 标题 | 内容 |
| --- | --- | --- |
| A | 日期 | `周一 11/23`，跨行合并 |
| B | 事件（一句话，链到日记那一条） | 指向该事件标题的链接 |
| C | 内心 | 该事件的洞察 |
| D | 行动 | 该事件的计划（What ｜ When） |
| E | 结果 | 该事件的简述 |
| F | 备注 | 手写状态词 |
| G | 笔记 | `[[日期]] · ★重要度 · 📌×N` |

### 3.2 版式规则

```
+-----------+--------------------------+----------+----------+----------+------+----------+
| 日期      | 事件                      | 内心      | 行动      | 结果      | 备注 | 笔记      |
+-----------+--------------------------+----------+----------+----------+------+----------+
| 周一 11/23| 📌事件①                  | 洞察①     | 计划①     | 简述①     | 新起 | [[1123]] |
| (合并 4 行)| 📌事件②                  | 洞察②     | 计划②     | 简述②     | 单独 | [[1123]] |
|           | 📌事件③                  | 洞察③     | 计划③     | 简述③     | 延续 | [[1123]] |
|           | 📌事件④                  | 洞察④     | 计划④     | 简述④     | 延续 | [[1123]] |
| 周二 11/24| 暂无日记记录              | —        | —        | —        | —    | —        |
| …         |                          |          |          |          |      |          |
| 周日 11/29| 暂无日记记录              | —        | —        | —        | —    | —        |
| 总结：主线 / 最大变化 / 可核对的结果 / 没解决的事 / 下周只做一件事          （横向合并 7 列）|
+-----------+--------------------------+----------+----------+----------+------+----------+
```

- 某天 N 个事件 → N 行；**没有日记的那天也要占 1 行**，事件格写「暂无日记记录」
- 只有「日期」列合并，其余列每行独立写满（没内容也写 `—`，不要留空，避免和「合并继承」混淆）
- 最后一行是总结行，横跨 7 列
- 表格上方要有：`# W48 · 2026-11-23 ~ 11-29（ISO 第 48 周）` + 周期 + 覆盖（`n / 7 天有日记｜事件 m 条`）

### 3.3 如果非要输出 Markdown 表（可手改）

Markdown 表格本身不支持合并，本项目用插件 **gogoga-table** 的注释实现：

```markdown
| 日期 | 事件 | 内心 | 行动 | 结果 | 备注 | 笔记 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 周一 11/23 | … | … | … | … | 新起 | … |
|  | … | … | … | … | 单独 | … |
<!-- gogoga-table: {"w":[88,190,null,null,null,120,150],"merge":["A2:A5","A12:G12"],"va":["middle"],"headerCol":true} -->
```

注释的硬规则（错一条就是**静默失效**，不报错）：

1. 紧跟表格最后一行，中间不能有空行，独占一行
2. 必须是合法 JSON 单对象，行内不能有裸 `|`
3. 坐标：列 A、B、C…；**表头是第 1 行，`---` 分隔行不计行号**，第一个数据行是第 2 行
4. 范围 `左上:右下`，至少覆盖 2 格（`A2:A2` 会被插件丢弃）
5. 不能从表头跨进正文（`A1:A3` 非法）
6. 内容写在左上角那格，其余格**必须留空**（否则合并后文字重复）
7. Markdown 源里每行 `|` 数量必须一致，不能因为合并就删竖线
8. 多个区间不能重叠
9. **坐标是位置不是内容**：行数一变必须整体重算

## 4. 两种可行实现（二选一）

### 方案 A：Templater 在“插入时”把表生成出来（静态表，可手改）

- 模板文件里放一段 `<%* … %>`，用 `app.vault.getMarkdownFiles()` / `await app.vault.read(file)` 读本周日记
- 数出每天几个 `## 📌` → 输出 N 行 Markdown + 算好的 merge 注释
- 插入到 `W49.md` 就是完整表格，之后可以随便改文字
- 缺点：**生成一次**。日记里加了事件，要重新插一次或手动加行 + 改 merge

### 方案 B：一个 `dataviewjs` 块直接渲染表格（推荐，自动更新）

- 整块代码粘进 `W49.md`，运行时读 7 天日记，用 **HTML `<table>` + `rowspan`** 直接画表
- 优点：`rowspan` 是浏览器级合并，**不用 gogoga 插件、不用算坐标、不用手加行**；日记改了切一下模式就更新
- 缺点：表格是渲染出来的，不能直接点进去改某个格子（要改进日记）

**本项目最终想要的是 B**（“插进去就自动显示，不要事后手改”）。参考实现见 §8。

## 5. 已试过并失败的做法（别重复踩）

| 做法 | 结果 |
| --- | --- |
| 单元格里写 `$= await WRF(dv).mind(...)`（Dataview inline 查询 + await） | **整格空白**。inline 查询不解析 Promise，不报错 |
| 顶部 `dataviewjs` 块定义全局函数、单元格写 `$= WRF(dv).mind(...)`（同步） | 空白或「—」。inline 查询和顶部代码块是两次独立渲染，格子先跑时数据还没读进来 |
| 整张表用 `dv.table()` 输出 | 输出的是 HTML，gogoga 注释对它无效，**无法合并单元格** |
| 固定 7 行（一天一行），格子内用 `<br>` 堆多个事件 | 能读但信息挤在一格，不符合「一行一件事」 |
| 纯 Markdown 模板（无代码）插进别的周文件 | 插入不改行数，永远是模板那几行 |

## 8. 参考实现（已验证：在 Node 里执行同一份代码、读真实日记，能取到内容并画出合并表）
