【周报模板 · 静态版（全文无代码）｜写给 AI 也写给人工】

插入到周报后，请把开头这条注释（从百分号包裹的开头到结尾分隔线）整块删掉。

■ 成品长什么样
周报 = 一张静态 GFM 表 + 紧贴表下的一行注释 `<!-- gogoga-table: {…} -->`。
没有脚本、没有 inline 查询、没有 dataviewjs。格子是写死的字，改完必须手动重算 merge。
周次用 ISO 8601（周一至周日）。例：W47 = 2026-11-16 ~ 11-22；W48 = 2026-11-23 ~ 11-29。
文件名按库中现状 `W{n}.md`，放在 `Diary\YYYY\` 下。

■ 数据来源（只读当天日记，不改日记）
`Diary\YYYY\YYYYMMDD.md`，一个文件一天，可能 0~5 条事件：
  事件标题 ← 每个 `## 📌 标题`
  内心     ← 该事件 `### 🔍 分析` 里的 `- 洞察::`
  行动     ← 该事件 `### 🎯 计划` 里的 `What::` ｜ `When::`（原文没写就写 —）
  结果     ← 该事件 `### 📝 简述` 正文（去掉「第N件事：」前缀）
  重要度   ← `- 重要度:: N`（没有就写 ★?，不要编）
  备注     ← 自己判断：新起 / 延续 / 调整 / 转折 / 收束 / 单独；跨周事件再加 event-YYYY-NNN
一格 ≤150 字，超了截断加「…」；细节靠「事件」列的链接回原文。
格子里要能核对的数字（时长 / 次数 / 金额 / 日期），不写「有进步」「效果不错」。

■ 排法（一条事件一行，这是本模板的核心）
1. 一天 N 件事 = N 行；日期只写当天第一行，第 2 行起日期格留空。
2. 没有日记的那天占 1 行，事件格写「暂无日记记录」；有文件但没 📌 事件写「有日记，但无 📌 事件」。
3. 最后一行是总结行，横跨 7 列，只写：主线 / 最大变化 / 可核对的结果 / 没解决的事 / 下周只做一件事。
4. 一周正常 7~12 行。禁止把一天的多个事件用换行塞进一个格子。
5. 表格上方必须有两行：`# W{n} · YYYY-MM-DD ~ MM-DD（ISO 第 n 周）` 和覆盖说明 `n / 7 天有日记｜事件 m 条`。

■ merge 坐标（算错了不会报错，只会安静地合并错格子）
表头 = 第 1 行，`---` 分隔行不计，第一个数据行 = 第 2 行。
  一天 N 行、从第 p 行开始 → `A{p}:A{p+N-1}`；N = 1 的那天不写区间（单格会被插件丢弃）。
  总结行在第 R 行 → `A{R}:G{R}`，R = 数据行数 + 1。
其余硬约束：单行合法 JSON、紧贴表尾不留空行、不跨表头、区间不重叠、左上角有内容且其余格留空、
每行竖线数量不变、JSON 里不出现裸 `|`。增删行之后整条重写，不要只改数字。

■ 链接写法
`[[YYYYMMDD#📌 标题\|显示文字]]` —— 表格里必须用 \| 转义竖线，否则整张表塌列。
标题必须与日记里 `## 📌` 后面那串字逐字一致，改一个字链接就打不开。

■ 交付前自检
□ 每行 7 个单元格；□ merge 行号 <= 数据行数+1、列号 <= 7；□ 每个区间 >= 2 格且不重叠；
□ 左上角有内容、从属格为空；□ 事件链接能在日记里点开；□ 全文没有代码块、没有任何 dataview 查询语法；
□ 备注只有六个状态词之一；□ 空值全表统一写 —

■ 实例（照这两个文件抄结构，别抄内容）
`Diary\2026\W47.md` —— 第 47 周成品：8 个事件，周四 / 周六 / 周日各 2 行合并。
`Diary\2026\W48.md` —— 第 48 周测试：周一 4 个事件合并成 A2:A5 + 6 天占位。
