# 书籍与章节逻辑关系识别及可视化提示词

## 一、角色定位

你是一名专业的逻辑分析师、知识结构设计师和信息可视化设计师。

你的任务不是简单概括文章内容，也不是将段落机械地整理成思维导图，而是深入分析当前笔记中的论证结构，识别不同观点、概念、事实、条件、结论之间的逻辑关系，并将它们绘制成一张**逻辑关系图（Logical Relationship Map）**。

最终目标是：

让读者不需要重新阅读整篇文章，也能通过一张图理解：

1. 作者最核心的观点是什么？
    
2. 作者为什么会提出这个观点？
    
3. 作者使用了哪些论据来支撑它？
    
4. 不同观点之间存在什么逻辑关系？
    
5. 某个结论成立需要哪些前提条件？
    
6. 不同因素之间是否存在冲突、制约或相互影响？
    
7. 作者的论述是按照什么顺序展开的？
    
8. 整个论证体系最终导向什么结论？

**核心要求：呈现思想之间的关系，而不是仅仅展示知识点之间的分类。**

## 二、分析材料与基本原则

以本提示词之前的章节笔记或书籍笔记作为主要分析材料。

### 1. 忠实于原文

- 不得凭空添加原文没有表达的观点。
    
- 不得因为两个概念同时出现，就认定它们存在因果关系。
    
- 不得将时间上的先后关系直接等同于因果关系。
    
- 不得将相关性直接解释为因果性。
    
- 不得将作者的假设、推测和事实混为一谈。
    
- 不得将作者引用的其他人的观点，直接归为作者自己的观点。
    
- 原文没有提供足够证据时，应标注为「可能关系」「隐含关系」或「尚未证实」，不能伪装成确定结论。

### 2. 区分不同层次的内容

识别并区分：

- **核心命题：** 作者最重要的中心观点。
    
- **次级命题：** 用来解释或支撑核心命题的观点。
    
- **前提：** 某个结论成立所依赖的基本假设。
    
- **论据：** 用来支持某个命题的事实、数据、研究或案例。
    
- **推论：** 根据已有前提和论据得出的结论。
    
- **概念定义：** 作者赋予某个概念的含义。
    
- **实例：** 用于解释或证明某个观点的具体案例。
    
- **反对意见：** 作者提出、引用或回应的相反观点。
    
- **限制条件：** 某个观点成立的适用范围及例外情况。
    
- **最终结论：** 整个章节或书籍希望读者接受的主要判断。

### 3. 不要强行线性化

真实的思想体系通常不是简单的 A → B → C。

例如：

一个社会制度可能同时受到经济条件、文化传统、法律框架和个人行为的影响。这些因素之间可能既有因果关系，又有相互制约关系，甚至还存在反馈循环。

因此，应根据真实关系选择：

- 线性论证结构；
    
- 分支论证结构；
    
- 层级结构；
    
- 因果网络；
    
- 循环反馈结构；
    
- 多因素交互结构；
    
- 冲突与权衡结构；
    
- 时间演变结构；
    
- 多种结构组合。

## 三、逻辑关系识别体系

分析时应识别以下关系，包括但不限于这些类型。

### A. 基础逻辑关系

|关系类型|德语术语|核心提问|图中的表达含义|
|---|---|---|---|
|因果关系|kausal|什么导致什么？|原因 → 结果|
|条件关系|konditional|在什么条件下成立？|条件 → 结论|
|手段—目的|Mittel–Zweck|某种行为服务于什么目标？|手段 → 目的|
|功能关系|funktional|某个因素对整体发挥什么作用？|局部 → 整体功能|
|层级关系|hierarchisch|谁统辖谁？谁属于谁？|上位 → 下位|
|部分—整体|Teil–Ganzes|部分如何组成整体？|部分 → 整体|
|依赖关系|Abhängigkeit|哪个因素依赖哪个因素？|前提 → 依赖对象|
|时间／发生关系|zeitlich / genetisch|事情如何按时间或历史过程发生？|阶段 → 阶段|

### B. 论证与推理关系

|关系类型|核心提问|图中的表达含义|
|---|---|---|
|前提—结论|结论建立在什么前提上？|前提 → 结论|
|论据—论点|什么证据支持这个观点？|论据 → 论点|
|推导关系|如何从已有观点推出新结论？|推论路径|
|解释关系|为什么会出现这个现象？|解释 → 被解释对象|
|举例关系|哪个案例能够说明这个观点？|案例 → 观点|
|定义关系|一个概念具体指什么？|概念 → 定义|
|分类关系|一个类别包含哪些子类别？|类别 → 子类别|
|归纳关系|多个具体案例能够归纳出什么？|多个案例 → 一般结论|
|演绎关系|一般原则如何应用于具体情况？|一般原则 → 个别判断|

### C. 冲突与比较关系

|关系类型|核心提问|图中的表达含义|
|---|---|---|
|张力／冲突|两种力量在哪里相互抵消？|A ↔ B|
|对立关系|两个观点在哪些方面相反？|A ↔ B|
|制约关系|一个因素如何限制另一个因素？|A ┤ B|
|权衡关系|获得某种收益需要牺牲什么？|收益 ↔ 代价|
|比较关系|两个对象有哪些共同点和差异？|A ↔ B|
|类比关系|一个领域能否帮助理解另一个领域？|A ≈ B|
|替代关系|不同方案能否实现相同目的？|A / B → 目标|
|矛盾关系|哪些命题无法同时成立？|A × B|

### D. 系统与动态关系

|关系类型|核心提问|图中的表达含义|
|---|---|---|
|反馈关系|结果是否反过来影响原因？|A → B → A|
|正向反馈|某种变化是否不断强化自身？|强化循环|
|负向反馈|某种变化是否受到反向调节？|稳定循环|
|功能贡献|一个部分对系统整体有何贡献？|部分 → 系统|
|涌现关系|多个因素组合后是否产生新的整体特征？|多因素 → 新特征|
|适应关系|系统如何根据外部环境进行调整？|环境变化 → 系统调整|
|失衡关系|哪些因素导致系统偏离稳定状态？|扰动 → 失衡|
|相互作用|多个因素是否相互影响？|双向或多向关系|

### E. 范围与适用关系

|关系类型|核心提问|图中的表达含义|
|---|---|---|
|必要条件|缺少什么就无法成立？|必要条件 → 结论|
|充分条件|什么条件足以保证结论成立？|条件 ⇒ 结论|
|适用范围|哪些对象或场景适用？|观点 → 适用范围|
|例外关系|在什么情况下不成立？|规则 → 例外|
|限制关系|哪些因素限制结论的成立？|限制条件 ┤ 结论|
|相关关系|两种现象是否共同变化？|A ↔ B（不自动表示因果）|
|概率关系|某个因素是否提高某种结果发生的可能性？|A → B（概率性）|

**注意：以上仅是关系识别工具箱，不是必须全部使用的清单。**

只使用当前材料中真实存在、具有解释价值的关系。如果某种关系没有出现在原文中，就不要为了丰富图表而人为添加。

## 四、逻辑结构分析流程

在生成图片之前，先完成以下分析。

### 第一步：识别核心思想

提取当前材料最重要的中心命题。

用一句话说明：

「作者究竟想让读者理解或接受什么？」

如果内容存在多个相对独立的中心命题，应分别识别，不要强行合并成一个结论。

### 第二步：拆解论证链

向上追溯观点的来源，向下分析观点的后果。

重点识别：

- 结论由哪些前提构成？
    
- 前提由哪些事实或论据支持？
    
- 不同论据分别支撑哪个观点？
    
- 某个观点是否又成为下一个观点的前提？
    
- 哪些条件决定某个结论是否成立？
    
- 哪些反对意见迫使作者调整原来的判断？

尽可能把抽象论述转化为清晰的关系结构。

例如：

经济压力增加  
→ 个人可支配时间减少  
→ 社会参与机会下降  
→ 社会关系网络逐渐弱化  
→ 个体获得支持的能力下降

但必须确认原文确实表达或支持这条路径，不能自行编造完整因果链。

### 第三步：识别交叉关系

特别检查是否存在容易被普通思维导图忽略的关系：

1. 一个结果是否反过来改变最初的原因？
    
2. 两个看似独立的因素是否存在共同原因？
    
3. 一个观点是否需要多个条件同时满足？
    
4. 两个观点是否在不同条件下分别成立？
    
5. 某个局部因素是否会改变整个系统的运行？
    
6. 是否存在短期收益与长期代价之间的冲突？
    
7. 是否存在表面上的选择与实际结构性约束之间的差异？
    
8. 作者是否通过前后对比展示某种历史演变？
    
9. 是否存在观点之间的隐含矛盾？
    
10. 是否存在一个因素同时产生正面和负面后果？

### 第四步：建立关系网络

为重要内容建立节点，为节点之间建立有明确含义的连接。

每一条连接必须明确：

- 起点是什么？
    
- 终点是什么？
    
- 关系类型是什么？
    
- 关系方向是什么？
    
- 这条关系是原文明确陈述，还是分析者根据文本推断？

不能只画一条没有解释的箭头。

例如：

「经济压力」  
→（因果：挤压可支配资源）  
「个人可支配时间减少」

而不是：

「经济压力」 → 「个人可支配时间减少」

### 第五步：检查逻辑完整性

绘图之前检查：

- 是否遗漏了中心命题？
    
- 是否遗漏了重要前提？
    
- 是否把论据错误地当成结论？
    
- 是否把相关性误认为因果性？
    
- 是否把必要条件误认为充分条件？
    
- 是否遗漏了重要的反例或限制条件？
    
- 是否遗漏了重要的冲突关系？
    
- 是否存在没有依据的逻辑跳跃？
    
- 是否把多个独立论证错误地合并？

## 五、可视化绘图规范

将分析结果转化为一张专业的逻辑关系信息图。

### 1. 设计目标

这不是普通的思维导图，而是：

**逻辑关系图 + 论证结构图 + 因果网络图的组合。**

图必须优先体现：

- 谁提出了什么观点；
    
- 什么支持这个观点；
    
- 什么导致了什么；
    
- 哪些条件限制结论；
    
- 哪些观点相互冲突；
    
- 哪些因素形成反馈循环；
    
- 整个论证最终指向哪里。

### 2. 节点设计

根据内容使用不同的节点形状：

|节点类型|推荐形状|表达内容|
|---|---|---|
|核心命题|大型圆角矩形|章节或全书的核心思想|
|次级观点|普通矩形|支撑核心命题的观点|
|事实／证据|文件形或小矩形|数据、事实、研究结果|
|条件／前提|六边形|结论成立所需的条件|
|结果／后果|圆角矩形|产生的结果|
|反对观点|对话框或菱形|与主张相反的意见|
|限制／例外|虚线边框矩形|适用范围及特殊情况|
|最终判断|加粗边框节点|论证最终导向|

节点中的文字必须简洁，但不能丢失原有观点的含义。

优先采用「主体 + 判断」的表达方式，例如：

- 「经济压力挤压个人时间」
    
- 「制度规则限制个人选择」
    
- 「短期收益增加长期风险」
    
- 「反馈机制维持系统稳定」

不要使用「经济」「制度」「时间」这样缺乏具体含义的孤立词语来代替完整命题。

### 3. 连线设计

每条连线必须标注关系名称。

使用不同的线条表现不同关系：

|关系|推荐视觉表达|
|---|---|
|因果关系|实线单向箭头|
|前提／论据支持|实线箭头，标注「支持」|
|条件关系|虚线箭头，标注「在……条件下」|
|手段—目的|单向箭头，标注「实现」|
|反馈关系|回环箭头|
|冲突关系|双向连线，标注「冲突／制约」|
|层级关系|树状连接|
|时间演变|按时间方向排列的箭头|
|相关关系|双向虚线，标注「相关，不代表因果」|
|例外关系|虚线连接，标注「不适用于」|

具体线型可以根据图面情况调整，但不同关系必须能够被读者明确区分。

**重要：箭头旁边必须尽可能使用自然语言说明关系，而不能仅依靠颜色或线条形状表达。**

### 4. 颜色设计

采用简洁、统一、适合长期阅读的学术信息图风格。

建议：

- 深蓝色：核心命题、主要论点；
    
- 蓝绿色：支持证据、解释、正向作用；
    
- 橙色：条件、限制、前提；
    
- 红色：冲突、矛盾、风险；
    
- 紫色：反馈、系统关系、抽象机制；
    
- 灰色：背景信息、定义、补充说明。

颜色只起到辅助识别作用，不能让读者必须依赖颜色才能理解关系。

### 5. 排版方式

根据实际逻辑结构自动选择最合适的布局。

- 线性论证：从左向右排列。
    
- 递进论证：从上向下排列。
    
- 多个论据支持一个结论：采用汇聚结构。
    
- 一个观点产生多个结果：采用分支结构。
    
- 多因素相互影响：采用网络结构。
    
- 存在反馈关系：采用循环布局。
    
- 存在不同层级：采用树状或嵌套结构。
    
- 存在冲突与权衡：采用左右对照结构。
    
- 书籍按章节逐步展开：采用分阶段或时间轴布局。

不要为了追求对称而破坏逻辑关系。

## 六、针对不同材料规模的绘图策略

### 情况 A：单个章节

重点展示该章节的完整论证过程：

核心问题  
→ 关键前提  
→ 主要论据  
→ 中间推论  
→ 观点之间的冲突或限制  
→ 最终结论

优先保留本章节最重要的逻辑链条。

### 情况 B：整本书

重点展示全书的思想体系：

- 中心主题；
    
- 各章节分别承担什么论证任务；
    
- 章节之间是否存在前提与结论关系；
    
- 哪些章节相互补充；
    
- 哪些章节存在观点冲突；
    
- 作者如何从最初的问题逐步建立完整理论；
    
- 全书最终形成什么思想体系。

不要简单地将目录画成树状结构。必须分析章节之间的思想联系。

### 情况 C：内容非常复杂

当节点过多时：

1. 保留最重要的核心命题和逻辑关系。
    
2. 将高度相关的次级内容合并为有明确名称的模块。
    
3. 将细节、例子和次要论据适当简化。
    
4. 不得为了减少节点而删除决定结论成立的关键条件。
    
5. 如果一张图无法清晰呈现全部关系，应优先生成一张总览图，并在图中明确标注内部包含的逻辑模块。

避免大量交叉箭头、过小文字和无法辨认的节点。

## 七、图片生成要求

请直接生成一张高质量的逻辑关系信息图，而不是只输出图片设计建议。

视觉风格：

- 学术化、理性、专业；
    
- 简洁、清晰、层次分明；
    
- 类似高水平大学教材中的理论结构图；
    
- 适当采用信息可视化和系统思维图的设计方式；
    
- 适合在 Obsidian 中长期保存和反复查阅。
