    }

  }

## 附录 A：表格 / Dataview / 箭头 —— 三种结构的实测（2026-11-19 加入）

### A0. 先看机制（来自插件源码，不是推测）

1. **识别方式是扫描文档文本**：`/{([^{}]+)}/g`，然后跳过 math / codeblock / inline-code 三种上下文。
2. **锚定对象是编辑器里的行元素**：`view.domAtPos(pos)` 拿到位置对应的 DOM，再取该行元素。Dataview 渲染出来的 HTML 表格**不在文档文本里**，插件根本扫不到 → 箭头**不可能**指进 Dataview 输出。
3. **只有起点能带参数**：`isStart = (options.length !== 1)`。带 `|` 的就是起点；终点必须是**裸的 `{id}`**。所以：
   - 表格单元格里**只能**放裸 `{id}`（带 `|` 会同时破坏表格语法、并且被插件误判成起点）——而这恰好就是终点的正确写法。
   - 结论：**「箭头指向表格单元格」在语法上是成立的**，剩下的唯一变量是"渲染表格时能否精确锚定到单元格"。

起点写在表格外（带参数），终点裸写在单元格里。请看这两行之间的连线落在**整张表**、**某一行**、还是**某个格子**：

### A3. 实测 3：单元格里放自动值 + 裸锚点

这一格里的数字是 inline dataviewjs 实时算出来的（改日记它会跟着变），同一格里还带着裸 `{id}` 作终点。如果箭头能指到这一格，就等于「自动化数值 + 可连线」同时成立：

### A4. 可行性矩阵

| 结构 | 能否被箭头锚定 | 依据 |
|---|---|---|
| 普通段落 / 列表项 | ✅ 可以 | 文档文本 + 行元素，插件的标准用法 |
| 原生 Markdown 表格单元格 | ⚠️ 待你实测（A1） | 文本在文档里（裸 id 不破坏语法），但锚点精度取决于渲染后的 DOM |
| Dataview 表格 / 卡片 | ❌ 不可能 | 输出不在文档文本中，正则扫不到 |
| Dataview 输出的列表 | ❌ 不可能 | 同上 |
| 代码块 / inline 代码里 | ❌ 不生效 | 插件主动跳过这三种上下文 |
| Excalidraw 画布 | ✅ 可以（另一套机制） | 画布内箭头是 Excalidraw 自己的元素，与 Arrows 无关 |

### A5. 建议的架构（如果 A1 落到"整表"而不是"格子"）

- **数据层**：Dataview 表格/卡片，负责"每个时间周期自动收集事件与属性"。
- **锚点层**：一段**手写列表**（每月/每天一行），只写 `月份 + 一句话 + 裸 id`，箭头挂在这里。
- **关系层**：Excalidraw 画真正的链路图（你的习惯），靠 `event-2026-xxx` 与上面两层互链。
- 三层之间用 `[[2026年报#event-2026-001|事件链 001]]` 这种链接互跳，信息不会因为结构调整而丢。

> 需要提醒：Arrows 只在**实时预览**里渲染（插件是 CodeMirror ViewPlugin，没有阅读视图分支）。阅读视图、打印、PDF 导出里都不存在这些线；而 Dataview 表格在三种视图里都能显示。这也是为什么"数据用 Dataview、关系用 Excalidraw"更稳。
